## 1. 왜 다시 기획했나

이전 기획은 "필름을 찍고 → 하루가 끝나면 현상한다"는 은유 위에 서 있었습니다. 은유가 제품 규칙까지 지배하면서 다음 제약이 생겼습니다.

- **하루 1롤 강제** — 여러 날에 걸친 영상, 주제별 영상을 만들 수 없다.
- **미현상 블러** — 사용자가 자기가 방금 찍은 영상을 못 본다. 은유를 위해 기능을 뺐다.
- **지연 현상** — 만들고 싶을 때 못 만든다. 하루가 끝나야 한다.
- **AI가 안 보인다** — "현상"이라는 의식 뒤에 숨어서, 이게 AI 제품인지 필름 감성 아카이브 앱인지 구분되지 않는다.

원래 의도는 **AI 기반 숏폼 브이로그 제작 앱**이었고, 은유가 그 의도를 덮었습니다. 은유를 걷어냅니다.

### 버리는 것

`하루 1롤` · `현상(develop) 의식` · `미현상 블러(negative frame)` · `필름 그레인·퍼포레이션·edge print` · `12컷 목표` · `보관함(archive)이라는 탭 이름` · `지오펜스 기반 자동 수집`

### 남기는 것

3–5초 짧은 촬영 · 원본은 불변이고 조합은 별도(N:M) · 다크 팔레트 · 촬영 리마인더 · 푸시/위치 알림 인프라 · 인증/설정 전반

> 다크 팔레트는 남깁니다. 영상 앱에 어두운 배경은 은유가 아니라 기능입니다. 다만 앰버 safelight·필름 질감처럼 "필름임을 주장하는" 장식은 뺍니다.

## 2. 제품 한 줄 정의

> **짧게 여러 번 찍어두면, AI가 한 편의 숏폼 브이로그로 만들어 주는 앱.**

두 개의 명사만 있으면 제품이 설명됩니다: **재료**와 **완성작**.

## 3. 선택한 방향 — 스튜디오(작업대형)

홈은 **내 작업대**입니다. 담아둔 재료와 진행 중인 무비가 항상 여기 놓여 있고, 앱을 다시 열면 하던 작업을 이어서 합니다.

**전제:** 사용자는 결과물을 자기 손으로 통제하고 싶어 한다. AI는 주인공이 아니라 마지막에 붙는 강력한 도구다.

### 결정 기록

2026-07-28에 홈의 성격만 달리한 세 방향을 프로토타입으로 만들어 비교했습니다 — `오늘(AI 제안형)` / `스튜디오(작업대형)` / `레시피(의도 우선형)`. 비교 문서의 원래 추천은 레시피였고, **채택된 것은 스튜디오입니다.**

추천을 뒤집은 근거는 비교 문서 자신이 단 단서였습니다: 레시피 방향은 **레시피 카탈로그를 상시 운영해야** 성립하고, 그걸 감당할 사람이 없다면 스튜디오로 시작하는 편이 정직합니다. 스튜디오는 운영 비용이 0에 가깝고, 백엔드도 합성 잡 하나면 출발할 수 있습니다.

나머지 두 방향은 폐기가 아니라 **뒤 단계로 밀어둔 것**입니다(§10 참조). 세 방향은 배타적이지 않고 단계로 놓을 수 있습니다.

### 감수하는 것

- 첫 무비까지 탭 6–8회. 제안형(2회)·레시피형(3–4회)보다 길고, 이탈 지점이 많습니다.
- AI가 "도구"로 밀려나 제품 차별점이 흐려질 수 있습니다. 차별화는 **트레이와 재료 관리 경험**이 집니다.
- 트레이라는 개념은 학습이 필요합니다. 온보딩 한 장이 필요합니다.

## 4. 용어와 탭 이름

| 개념 | 이름 | 이유 |
| --- | --- | --- |
| 3–5초 원본 조각 | **스냅** (Snap) | 브랜드명 Snaply와 직결. 그대로 유지. |
| AI가 합성한 결과물 | **무비** (Movie) | "스냅↔무비 = 재료↔완성작" 대비가 즉시 읽히고 단위로도 자연스럽다("무비 3편"). 검토한 대안: `릴`(인스타 릴스와 충돌), `브이로그`(장르명이라 단위로 어색), `에피소드`(연재물 느낌), `컷`(스냅과 혼동). |
| 무비 안에서의 한 조각 | **컷** | 편집기 안에서만 쓰는 말. 스냅이 무비에 들어가면 컷이 된다. |
| 담아둔 스냅 묶음 | **트레이** | §5의 핵심 발명. |
| 홈 | **스튜디오** | 홈의 이름은 홈이 담는 것에서 나온다. |
| 프로필 + 설정 | **나** | 한 글자. `마이`, `프로필`보다 짧고 한국어 앱 관례에 맞다. |
| 촬영 | 탭바 중앙 ● 버튼 | 탭이 아니라 액션. 4탭 + 중앙 버튼 = 5슬롯(틱톡/인스타 관례). 어느 탭에서든 촬영 가능. |

**"폼"은 쓰지 않습니다.** 어원(필름)이 버릴 컨셉에 묶여 있고, 한국어에서 "폼"은 form(양식)으로 먼저 읽힙니다.

## 5. 정보 구조

```text
탭바:  [스튜디오] [스냅] (●촬영) [무비] [나]

스튜디오  담기 트레이 + 작업 중 보드 + 최근 완성. 앱을 다시 열면 여기서 이어서 한다.
스냅      내가 찍은 3–5초 원본. 날짜별 그리드. 즉시 재생 가능(블러 없음).
          우상단 [선택] → 다중 선택(최대 10) → [트레이에 담기].
무비      완성작 + 초안. 2열 그리드. 열면 재생 / 컷 수정 / 스타일 변경 / 재생성 / 공유.
나        프로필 · 통계 · 리마인더 · 알림 · 연결된 계정 · 계정 관리 (기존 설정 그대로).
```

### 핵심 발명 — 담기 트레이

스냅 탭에서 고른 스냅은 **곧바로 무비가 되지 않고** 스튜디오의 트레이에 쌓입니다. 장바구니와 같습니다.

- 여러 날에 걸쳐 재료를 모을 수 있습니다. "하루 1롤"이 풀리는 지점이 여기입니다.
- 트레이 상한은 **10개**이며, 이것이 제품의 유일한 하드 제약입니다(무비 1편 = 스냅 ≤10).
- 트레이는 앱을 껐다 켜도 유지됩니다. 무비를 시작하면 비워집니다.
- 스냅 탭의 셀에는 이미 트레이에 담긴 스냅임을 알리는 `담김` 배지가 붙습니다.

### 무비를 만드는 경로

경로는 항상 **두 개**입니다.

1. 스냅 탭에서 다중 선택(≤10) → `트레이에 담기` → 스튜디오 → `이 스냅으로 새 무비`
2. 스튜디오 / 무비 탭의 `+` → 스냅 선택 모드로 진입 → 위와 동일

## 6. 편집기 — 3단계 위저드

무비는 항상 이 3단계를 지나갑니다. 각 단계는 언제든 저장되고, 나가면 **초안**으로 스튜디오 보드에 남습니다.

| 단계 | 화면 | 하는 일 |
| --- | --- | --- |
| ① 조립 | 컷 리스트 | 순서 바꾸기(▲▼), 컷 빼기, 트림 구간 조정, `스냅 더 넣기`. 컷은 최소 1개. |
| ② 스타일 | 스타일 4종 + 세부 | `잔잔한` `경쾌한` `담백한` `감성적인` 중 하나 + 배경음악·자동 자막·비율(9:16)·목표 길이. |
| ③ 생성 | 진행 링 | `업로드 → 장면 분석 → 컷 다듬기 → 음악·자막 → 렌더` 5단계 진행 표시. 앱을 나가도 계속됨. |

**①에서 정한 순서와 트림은 그대로 유지됩니다.** AI는 전환·색보정·음악만 맡습니다. 이 규칙이 깨지면 편집 기능 자체가 무의미해집니다(§8의 합성 잡 요구사항과 직결).

무비 상태는 `draft`(초안) → `generating`(생성 중) → `ready`(완성)이며, 실패 시 `failed`입니다. 스튜디오 보드는 `ready`가 아닌 무비를 진행률과 함께 보여줍니다.

## 7. 콜드 스타트

스냅이 0개여도 홈이 비지 않습니다. 트레이 자리에 "스냅 탭에서 쓸 만한 장면을 골라 담기를 누르면 여기 모여요"가 놓이고, 버튼은 스냅 선택 모드로 바로 데려갑니다. 작업 중 보드가 비면 그 자리도 문구로 채웁니다.

촬영 유도는 이 방향의 약점입니다(§3). 촬영 리마인더(기존 `나` 탭 설정)가 당분간 그 역할을 대신합니다.

## 8. 데이터 모델과 기존 코드 매핑

핵심: **모델은 거의 그대로 쓸 수 있습니다.** 바꿀 것은 이름과 규칙이지 구조가 아닙니다.

| 지금 | 바뀔 것 | 비고 |
| --- | --- | --- |
| `entities/clip` · `Clip` | `entities/snap` · `Snap` | 필드 거의 동일. `mood`는 재검토(캡처 옵션 대신 무비 스타일로 이동). |
| `entities/roll` · `Roll` + `Reel` | `entities/movie` · `Movie` | 롤과 릴을 하나로 합친다. 릴은 "developed된 롤"이 아니라 무비의 렌더 산출물. |
| `ClipRef { clipId, order, trim }` | `SnapRef` 그대로 | N:M + per-무비 순서/트림 구조는 그대로 유효하고, 편집기 ①단계가 정확히 이 구조를 편집한다. |
| `RollStatus: undeveloped / developing / developed` | `MovieStatus: draft / generating / ready / failed` | `failed` 추가 필수 — AI 잡은 실패한다. |
| `RollType`, `CollectionRule`, `DailyRollTarget(12)`, `dayKey` | 삭제 | 하루 1롤·자동 수집 규칙을 버리므로 전부 불필요. |
| — | `Movie.style`, `Movie.bgm`, `Movie.jobId`, `Movie.renderedUri` | 신규. |
| — | 트레이 상태(스냅 ID 목록, ≤10) | 신규. 무비가 아니므로 별도 슬라이스가 필요하다. |

영향 범위(구현 착수 시 `docs/architecture`·`docs/conventions` 규칙으로 재확정):

- `features/`: `collect-clips` + `develop-roll` → `compose-movie`로 통합. 트레이는 별도 슬라이스 후보. `capture-moment`는 유지.
- `widgets/`: `roll-shelf`(월별 현상 선반)는 스튜디오 보드 요구에 맞춰 재작성, `clip-membership`(역인덱스)은 그대로 쓸 수 있다.
- `pages/`: `home` · `archive` · `roll-detail` · `cut-strip` → `studio` · `snaps` · `movies` · `movie-editor`로 재편.
- `shared/ui/`: `negative-frame`(미현상 블러), `film-grain` → 제거 대상.
- `docs/features/`: 전 문서 재작성 대상.

## 9. 백엔드에 필요한 계약 (초안)

```text
POST  /snaps                  스냅 업로드 (video + 메타: 촬영시각, 길이, 위치, 해상도)
GET   /snaps?cursor=          내 스냅 목록

POST  /movies                 { snapIds[] (≤10), order[], trims[], style, bgm, ratio }
                              → { movieId, jobId, status: "generating" }
GET   /movies/:id             → { status: draft|generating|ready|failed, renderedUrl?, error? }
PATCH /movies/:id             초안 저장 (순서/트림/스타일) — 재생성 없이
POST  /movies/:id/regenerate  같은 스냅 세트로 다시 합성 (seed/style 변경)
GET   /styles, GET /bgms      스타일·BGM 카탈로그
```

두 가지가 반드시 필요합니다.

1. **순서·트림 보존 모드.** 사용자가 편집기에서 정한 순서와 트림을 합성 잡이 그대로 지켜야 합니다. AI가 다시 정렬하면 안 됩니다.
2. **초안의 서버 저장.** `PATCH /movies/:id`로 순서·트림·스타일을 서버에 유지해야 기기를 바꿔도 작업이 이어집니다.

알림도 하나 필요합니다: **무비 완성 푸시.** 합성이 40초씩 걸리면 사용자는 앱을 나갑니다. 기존 FCM 인프라를 그대로 씁니다.

## 11. 아직 안 정한 것

- **공유/소셜을 넣을 것인가.** 지금은 "내보내기 + 외부 앱 공유"만 가정했습니다. 앱 안에 피드가 생기면 탭 구조가 다시 바뀝니다.
- **무비 길이 상한.** 스냅 10개 × 5초 = 최대 50초. 숏폼 기준으로는 적당하지만, 트림으로 줄일지 목표 길이를 먼저 정할지 미정.
- **스냅 보관 정책.** 원본을 서버에 올릴지, 기기에만 두고 합성 때만 업로드할지. 용량·비용·계정 이전이 전부 여기에 걸립니다.
- **트레이를 여러 개 둘 것인가.** 지금은 1개입니다. 주제별로 동시에 모으고 싶다는 요구가 나오면 재검토합니다.
