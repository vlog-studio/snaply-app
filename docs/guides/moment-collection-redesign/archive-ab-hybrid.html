archive · A+B hybrid · spec v0.1 · 2026-07-27

캐비닛 위에
네거티브 스트립.

4안 비교에서 A + B 하이브리드로 확정했습니다. 보관함 최상위는 필름 캐비닛(현상 대기 → 월별 선반 → 컷 서랍), 서랍 안은 컨택트 스트립(퍼포레이션 스트립 · 롤 색 점 · 컨텍스트 3액션)입니다. 이 문서는 그 결정을 화면·상태·모션·슬라이스까지 내린 구현 설계입니다.

최상위 · /archive
필름 캐비닛 (A)

세그먼트 제거. 한 줄 스크롤로 현상 대기 → 월별 현상 완료 선반 → 컷 서랍. 커버는 첫 프레임 4-업 모자이크. 리텐션 훅이 수집 공간 안으로 들어옵니다.

컷 레이어 · /cuts
컨택트 스트립 (B)

하루 = 가로 35mm 퍼포레이션 스트립. 롤 소속은 프레임의 색 점(N:M), 액션은 필터 컨텍스트에 따라 달라지는 3액션. 삭제가 유일한 액션이 아니게 됩니다.

새 롤로 묶기 포함 — 수동 롤 생성을 MVP 범위로 확장하기로 확정(§3·§7).

01

구조와 라우트

expo-router

컷 서랍은 탭 안의 세그먼트가 아니라 루트 스택 푸시 라우트입니다. 선례는 이미 있습니다 — 설정도 탭에서 빠져 settings로 루트 스택에 등록돼 있습니다(_app/routes/root-layout.tsx).

(tabs) ├── / 오늘 (홈) └── /archive 보관함 = 필름 캐비닛 (A) ├─ 현상 대기 카드 ──── /roll/[id] 컨택트시트 (기존) │ └ 현상하기 → /capture/editing?rollId= ├─ 월별 선반 커버 ──── /capture/result?rollId= 릴 재생 (기존) ├─ 컷 서랍 ─────────── /cuts 컷 = 컨택트 스트립 (B) ★신설 └─ ⚙ ──────────────── /settings (기존, 유지) 루트 스택 (인증 그룹) └── /cuts ★신설 · 탭바 없음 · 헤더 ‹ 컷 ├─ 필터: 전체 · 미현상 · 롤 없음 N · 롤별 ▾ ├─ 길게 눌러(또는 헤더 선택) → 선택 모드 → 컨텍스트 3액션 ├─ 컷 탭 → 컷 시트 (재생 · 이 컷이 든 롤 · 빼기 · 삭제) └─ 삭제 → 2단 분리 확인 다이얼로그

/cuts를 /archive/cuts로 두지 않은 이유

(tabs)/archive.tsx가 이미 /archive를 소유합니다. 같은 경로 아래 디렉터리 라우트를 겹치면 그룹과 디렉터리가 한 경로를 나눠 갖는 모호한 구조가 됩니다. settings와 같은 방식(루트 스택 형제 라우트)이 이 프로젝트의 확립된 패턴이므로 그대로 따릅니다.

부수 효과 하나: 선택 모드가 탭바 없는 라우트로 옮겨가면서 shared/ui/tab-bar-chrome(탭바 숨김 스위치)의 유일한 소비자가 사라집니다. 확인 결과 소비자는 pages/archive와 그것을 읽는 _app/routes/app-tabs뿐이므로, 이 작업에서 같이 제거합니다.

02

필름 캐비닛

/archive

위에서 아래로 기대 → 소유 → 원본 순서입니다. 현상 대기(오늘 포함) → 월별 현상 완료 선반 → 컷 서랍.

확정 규칙

  • 현상 대기 레인은 항상 존재합니다. 오늘의 롤은 컷 0개여도 카드로 남습니다(DailyRollGate가 보장). "대기 0"인 상태는 있을 수 없으므로 이 레인에 빈 상태가 필요 없습니다.
  • 현상 준비됨 = status: 'undeveloped' + dayKey < 오늘 + clipRefs.length > 0. 컷 0개인 지난 롤은 현상할 게 없으므로 레인에서 제외하고 조용히 넘깁니다.
  • 냉광 스윕은 "현상 준비됨" 카드에만. 오늘 카드는 앰버 계열 정지 상태입니다. 냉광은 컨셉 §5대로 "현상하는 순간"의 색이므로, 아직 담는 중인 롤에 쓰면 의미가 흐려집니다.
  • 선반은 월별 섹션. 헤더는 현상 완료 · YYYY.MM + 그 달 롤 수. 월이 끝날 때마다 N일 비었음 슬롯 하나 — 값은 그 달의 경과일 − 컷이 있는 날로 계산하며, 미래 날짜는 세지 않습니다.
  • 커버 = 첫 프레임 4-업 모자이크 + 3px 각인 띠. 썸네일은 이미 캐시돼 있어 새 I/O가 없습니다(shared/lib/video-thumbnails, base name 키). 컷이 4개 미만이면 있는 만큼 반복해 채웁니다.
  • 장식용 빈 롤 점선 슬롯은 삭제. 눌러지지 않는 거짓 어포던스였고, 그 자리를 N일 비었음(실제 값, 그 달로 스크롤)이 대신합니다.
홈 화면에 번지는 변경

pages/home이 widgets/developed-rolls-shelf의 formatReelLength를 직접 임포트합니다. 이 위젯을 상태별로 쪼갤 때 홈의 임포트도 같이 옮겨야 합니다. 홈의 선반 미리보기도 같은 read model을 쓰므로 커버 모자이크가 홈에 자동으로 따라옵니다 — 의도된 이득이지만 홈 목업과 대조해 확인이 필요합니다.

자유 롤은 캐비닛에서 어디에 앉나

캐비닛은 날짜로 조직됩니다(현상 대기 → 월별 선반). 그런데 수동으로 묶은 자유 롤에는 dayKey가 없습니다 — dayKey는 데일리 롤 전용 필드입니다. 그래서 자리와 표기를 명시적으로 정해둡니다.

질문결정이유 · 확인
미현상 자유 롤은 어느 자리? 현상 대기 레인에 데일리와 나란히. 조건에서 dayKey를 빼고 status === 'undeveloped' && clipRefs.length > 0로 통일 현상할 수 있는 롤이 전부 한 자리에 모여야 "대기"라는 말이 성립합니다
레인이 길어지면? 오늘의 롤 + 최근 2개까지 펼치고 나머지는 +N개 더로 접기 자유 롤은 수동 생성이라 개수 상한이 없습니다. 접지 않으면 선반이 화면에서 밀려납니다
현상 완료 자유 롤은 어느 달 선반? rollDate = dayKey ?? createdAt의 달. 데일리는 그날, 묶음은 묶은 날 컷 조인 없이 계산되고, 컷이 여러 달에 걸쳐도 자리가 하나로 정해집니다
커버 제목 · 엣지 프린트 제목은 사용자가 준 이름, 엣지는 컷 날짜 범위 — 07-18~07-24 · 3컷 데일리는 날짜가 제목이라 엣지에 컷 수만 오지만, 자유 롤은 제목이 이름이므로 엣지가 날짜를 맡아야 합니다
오늘의 롤과 충돌하나? 없음. 그대로 둡니다 확인 완료 — ensureDailyRoll은 type === 'daily' && dayKey로 찾고 useTodayRoll은 todayRollId를 봅니다. dayKey 없는 롤은 어느 쪽에도 걸리지 않습니다
자유 롤도 현상되나? 됨. 현상 경로는 손대지 않습니다 확인 완료 — composeReel은 roll.type을 보지 않습니다(순서 정렬 + 지배 무드 BGM + 컷 수 기준 전환뿐)
롤 상세는? 기존 /roll/[id]가 그대로 처리. 엣지 프린트만 손봄 현재 ROLL · {dayKey ?? '—'}를 찍어 자유 롤이 —로 나옵니다. dayKey가 없으면 날짜 범위를 찍도록 바꿉니다
잘못 만든 롤은? 미현상 자유 롤의 컷이 0개가 되면 자동 제거. 데일리 롤은 유지 롤 삭제 UI를 새로 만들지 않고 막다른 상태를 막는 최소 규칙(§3 하위 결정 ③)
03

컨택트 스트립

/cuts

하루가 스트립 한 줄입니다. 프레임의 색 점이 롤 소속, 앰버 점선은 어느 롤에도 없는 컷, ?는 아직 채워지지 않은 오늘의 빈 슬롯입니다.

확정 규칙

  • 선택 바 3액션은 필터 컨텍스트에 따라 달라집니다. 롤에서 빼기는 "어느 롤에서"가 있어야 성립하므로, 롤 컨텍스트가 있는 롤별 필터에서만 나타납니다.
    전체 / 미현상 / 롤 없음 → [새 롤로 묶기] [롤에 담기] [삭제]
    롤별(롤 R 선택)     → [롤에서 빼기] [롤에 담기] [삭제]
  • 현상 완료 롤은 멤버십이 고정입니다. roll-detail이 이미 canEdit = status === 'undeveloped'로 강제하고 있습니다. 컷 시트의 빼기도 같은 규칙을 따라 비활성이고, 롤에 담기의 대상 목록에도 미현상 롤만 올라옵니다.
  • 프레임 점은 최대 3개까지 표시하고 그 이상은 +N으로 접습니다. 44px 프레임에 점 4개 이상은 읽히지 않습니다.
  • ? 빈 슬롯은 오늘 스트립에만. 지난 날의 스트립에 빈 슬롯을 남기면 "채우지 못한 과거"가 되어 톤이 어긋납니다. 소프트 타깃(12컷)은 오늘에만 유효합니다.
  • 선택 모드 진입은 두 경로 — 프레임 롱프레스(260ms, 기존 값 유지)와 헤더의 선택. 안드로이드 하드웨어 백은 선택 모드를 먼저 해제합니다(기존 동작 유지).
  • 스트립은 각각 가로 스크롤합니다. 하루에 컷이 많으면 그 줄만 밀리고 세로 리듬은 유지됩니다.
결정 — "새 롤로 묶기"는 MVP 범위로 확장 (2026-07-27)

기존 문서(recording-archive.md)가 수동 롤 생성을 범위 밖으로 두고 있었지만, 이번에 범위에 넣기로 확정했습니다. 근거는 단순합니다 — 컷과 롤을 N:M으로 나눈 이유가 "한 컷이 여러 롤에 산다"인데, 롤을 만들 수 없으면 데일리 롤 하나뿐이라 N:M이 실제로 발생하지 않습니다. 스트립의 색 점도 항상 1개짜리가 됩니다.

따라오는 하위 결정 셋 — 확장을 최소 표면으로 유지하기 위한 것들입니다.

① 성격(RollType) 칩은 노출하지 않고 free 고정. 성격은 BGM 톤·기본 길이·커버 스타일을 바꾸는 값인데 그 동작이 아직 구현되지 않았습니다. 칩 4개를 두면 눌러도 아무 일이 없는 가짜 컨트롤이 됩니다. 프리셋 카드는 v1.1 테마 롤과 함께 엽니다(컨셉 §3 "화면엔 프리셋 카드만, 풀 커스텀은 한 겹 뒤").

② 이름은 필수가 아님. 비우면 묶음 07-27이 들어갑니다. 20자 상한, 중복 허용. 이름 강제는 담기 마찰입니다.

③ 잘못 만든 롤은 자동 정리. 롤 삭제 UI를 새로 만들지 않습니다. 미현상 자유 롤의 컷이 0개가 되면 그 롤을 제거합니다(데일리 롤은 컷 0개여도 유지 — 오늘의 롤이 사라지면 안 됨). 막다른 상태를 UI 추가 없이 막는 최소 규칙입니다.

화면별 상태

화면로딩빈 상태에러

설계에서 바뀐 것 둘. ① removeRoll(id)를 공개 API로 두지 않고 빈 자유 롤 제거를 스토어 불변식으로 넣었습니다 — removeClipFromRoll·removeClipsEverywhere 양쪽에 적용해야 하는데(원본 삭제도 롤을 비웁니다) 호출자 둘이 각자 지키는 규칙은 결국 한쪽에서만 지켜집니다. 소비자 없는 removeRoll은 그래서 열지 않았습니다. ② fly-to-cover는 미구현 — /cuts에는 날아갈 커버가 화면에 없습니다(서랍→스트립과 같은 이유로 공유 요소 전환 미도입). 대신 새 롤의 틴트로 250ms ease-out-back 스냅 + medium 햅틱을 주는 확인 줄을 넣었습니다 — §7의 릴리즈 스냅과 햅틱은 살리고 비행만 뺀 것		 유닛: createManualRoll 기본 이름·20자 상한, 컷 0개 자유 롤 자동 제거, 데일리 롤은 0개여도 유지, rollDate 월 배치.

정직하게 남겨두는 것

롤 생성은 들어오지만 롤 성격은 아직입니다. 만들 수 있는 건 free 자유 롤 하나이고, 성격 칩·수집 규칙(기간·위치·태그)·지향 화면비는 노출하지 않습니다. 동작이 없는 값을 컨트롤로 세우지 않는다는 원칙(§3 하위 결정 ①)이고, 프리셋 카드는 v1.1 테마 롤과 함께 엽니다. 캐비닛이 월별 선반이라 나중에 날짜 범위 롤이 들어와도 구조는 버팁니다.

롤 이름 수정·롤 직접 삭제 UI는 없습니다. 이름은 생성 시 한 번, 삭제는 "컷을 다 빼면 사라진다"는 규칙으로만 도달합니다. 롤 관리 화면은 테마 롤이 생겨 롤이 많아진 뒤에 필요해집니다.

공유·내보내기는 여전히 없습니다. 컷 시트의 액션은 재생·담기·삭제뿐입니다.

웹은 그대로 프로토타입입니다. 웹 어댑터가 컷을 0개로 반환하므로 스트립은 빈 상태만 보입니다.

iOS 실기기 검증은 불가합니다(기기 없음). 시뮬레이터 + Android 실기기로 확인하고, 그 사실을 결과에 명시합니다.
