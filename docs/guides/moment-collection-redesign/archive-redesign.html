Archive redesign · proposal v0.1 · 2026-07-27

보관함,
창고에서 수집장으로.

지금의 보관함은 어두운 팔레트를 입은 갤러리 앱입니다. 컷 격자와 롤 커버가 나란히 있을 뿐, 컨셉의 두 축인 수집욕과 지연된 현상이 이 화면에 없습니다. 아래는 현재 화면 진단과, 서로 다른 전제에서 출발한 네 개의 방향 제안입니다.

이 문서는 사람 개발자용 제안 프로토타입입니다. 확정 방향이 아니며, 확정 시 docs/features/recording-archive.md에 반영합니다.

00

현재 보관함 진단

as-implemented

구현된 화면(src/pages/archive/ui/archive-page.tsx)을 그대로 목업으로 옮긴 것입니다. 기능은 대부분 동작합니다 — 문제는 동작이 아니라 이 화면이 무엇을 말하는가입니다.

핵심 진단 7

P1 · 수집욕
채울 자리가 없다

컨셉 §4의 "빈칸을 보여준다"가 장식용 빈 롤 하나로 축소됐습니다. 그마저 눌러지지 않아 거짓 어포던스입니다.

P2 · 리텐션
현상 대기가 없다

선반은 developed만 나열합니다. 앱의 훅인 "지연된 현상"의 기대감이 수집 공간에 존재하지 않습니다. 미현상 롤은 홈에서만 닿습니다.

P3 · 데이터 모델
N:M이 안 보인다

컷·롤을 나눈 이유가 N:M인데, 컷에 "어느 롤에 들어있나"도 "아무 롤에도 없다"도 표시되지 않습니다.

P4 · 액션
위험한 액션만 있다

컨셉 §3은 롤에서 빼기와 보관함에서 삭제 분리를 요구합니다. 선택 모드의 유일한 일괄 액션은 영구 삭제이고, 수집 쪽 액션(새 롤로 묶기)은 없습니다.

P5 · 시각 언어
필름이 팔레트로만 남았다

모티프인 퍼포레이션 필름 프레임이 없습니다. 3:4 라운드 썸네일 격자는 어떤 갤러리 앱과도 구분되지 않습니다.

P6 · 데이터 소스
컷 격자가 파일 목록이다

격자는 useLocalRecordings(파일)를 읽어 무드·길이·태그·방향을 구조적으로 못 씁니다. entities/clip엔 이미 다 있습니다.

P7 · 시간감
쌓인 게 안 보인다

스트릭·월 단위 축적·총량 감각이 없습니다. 커버는 실제 커버 아트 대신 순환 틴트라 "내 것"이라는 느낌이 약합니다.

A

필름 캐비닛

롤 우선

전제: 수집의 단위는 롤이다. 세그먼트를 없애고 한 줄 스크롤로 바꿉니다. 위는 현상 대기(오늘의 롤 포함), 아래는 월별 현상 완료 선반. 컷은 최상위 탭이 아니라 캐비닛 맨 아래 서랍으로 내려갑니다.

왜 이게 낫나

  • P2를 정면으로 해결. "현상 준비됨" 롤이 보관함 최상단에 라이트박스 톤으로 앉아, 리텐션 훅이 수집 공간 안에 들어옵니다.
  • 세그먼트 제거. 컷/롤 토글은 사용자에게 "둘 중 뭘 보고 싶냐"를 묻습니다. 대부분의 답은 롤이므로 기본을 롤로 두고 컷은 서랍으로 내립니다.
  • 커버가 내 것이 됩니다. 이미 캐시된 첫 프레임 썸네일 4장을 모자이크로 쓰면 순환 틴트(P7)가 사라집니다.
  • 빈칸이 월 단위로. "6월 · 4일 비었음"은 장식이 아니라 사실이며, 눌러 그 달을 보여줄 수 있습니다.

대가

  • 컷 일괄 삭제·선택이 한 단계 뒤로 밀립니다. 컷 관리를 자주 하는 사용자에겐 후퇴.
  • /archive/cuts 격자 라우트가 새로 필요합니다.
기존 데이터로 구현 가능중간 규모새 라우트 1개
B

컨택트 스트립

시간 우선

전제: 보관함은 내 삶의 한 줄 네거티브다. 세그먼트도 격자도 없이, 하루가 가로 35mm 스트립 한 줄입니다. 롤은 프레임에 붙는 색 태그로만 나타나고(N:M 그대로), 오른쪽에 월 레일로 점프합니다.

왜 이게 낫나

  • P5의 정답에 가장 가깝습니다. 퍼포레이션 스트립은 어떤 갤러리 앱과도 닮지 않았고, 컨셉 §5 모티프를 UI 구조 자체로 씁니다.
  • P3을 화면으로 표현. 프레임에 붙는 색 점이 곧 롤 소속이고, 두 점이면 두 롤에 든 컷입니다. N:M을 설명 없이 보여줍니다.
  • P4를 해결. 스트립 선택 모드가 새 롤로 묶기 / 롤에서 빼기 / 삭제 3액션으로 확장돼 컨셉 §3의 삭제 분리를 만족합니다.
  • "롤 없음 9" 칩이 주인 없는 컷을 노출해 새 롤을 만들 동기를 만듭니다.

대가

  • 하루에 컷이 많으면 가로 스크롤이 생깁니다(한 줄에 5컷). 밀도 튜닝이 필요합니다.
  • 현상 완료 롤을 골라 보는 경험은 A보다 약합니다. 릴 재생 진입이 스트립 라벨에 얹혀 작습니다.
  • 역인덱스(컷→롤 목록)가 필요합니다. roll.clipRefs로 계산 가능하지만 새 read model 위젯이 필요합니다.
시각적 차별화 최상밀도 튜닝 필요역인덱스 위젯
C

현상 워크벤치

상태 우선

전제: 보관함은 작업대다. 롤을 상태로 세웁니다 — 담는 중 → 현상 준비됨 → 보관 완료. 맨 위엔 필름 각인 스트릭, 맨 아래엔 축적 스탯. 현상 CTA를 보관함 안으로 끌어옵니다.

왜 이게 낫나

  • 리텐션 훅이 가장 강합니다. 보관함을 열면 "현상할 게 있다"가 라이트박스 연출과 함께 즉시 보입니다. 컨셉 §7의 냉광 스윕을 정지 화면에서도 씁니다.
  • P1·P7 동시 해결. 각인 스트릭(§4)과 축적 스탯이 "쌓고 있다"는 감각을 만듭니다.
  • 상태 3단이 RollStatus(undeveloped/developing/developed)와 1:1로 대응해 새 데이터가 거의 필요 없습니다.

대가

  • 가장 위험한 방향입니다. 상태 레인 + 스탯 + 스트릭은 대시보드 문법이고, 컨셉이 피하려는 "흔한 툴 앱" 쪽으로 기울 수 있습니다.
  • 스트릭은 공백을 실패로 채점합니다. 순간 수집 앱의 톤과 충돌할 수 있어 표현 수위 결정이 필요합니다.
  • 컷 관리가 이 화면에서 완전히 사라져, 별도 라우트가 필수입니다.
데이터 요구 최소훅 강도 최상대시보드화 위험
D

수집 캘린더

빈칸 우선

전제: 빈칸을 문자 그대로 보여준다. 한 달이 필름 프레임 격자입니다. 채운 날은 그날의 첫 프레임 + 상태 링(앰버=미현상, 냉광=현상 완료), 빈 날은 퍼포레이션 빈 프레임. 날짜를 누르면 그날의 롤 시트가 올라옵니다.

왜 이게 낫나

  • P1을 가장 직접적으로 해결. 컨셉 §4의 "빈칸을 보여준다"가 화면 구조 자체가 됩니다. 빈 날 프레임은 채우고 싶게 만듭니다.
  • 구현 비용이 가장 낮습니다. roll.dayKey가 이미 YYYY-MM-DD이고 첫 프레임 썸네일도 캐시돼 있어, 새 데이터 없이 조합만 하면 됩니다.
  • 상태 링 하나로 미현상/현상 완료가 한눈에 구분돼 P2도 부분 해결됩니다.
  • 과거 탐색이 스크롤이 아니라 월 점프가 되어, 데이터가 쌓일수록 유리합니다.

대가

  • 하루에 컷이 몇 개든 한 칸입니다. 많이 담는 날의 밀도를 표현하지 못합니다(카운트 숫자로 완화).
  • 공백이 격자에 남아 죄책감 UI가 될 수 있습니다. 톤 조절(빈칸을 조용히)이 중요합니다.
  • 여행 롤·테마 롤처럼 날짜 범위/규칙 기반 롤은 달력 한 칸에 안 들어갑니다. v1.1의 테마 롤과 충돌합니다.
구현 비용 최소수집욕 최상테마 롤과 충돌
05

비교와 추천

네 방향은 배타적이지 않습니다. A·C·D는 상위 구조를, B는 컷 표현과 액션을 바꿉니다.

축A 필름 캐비닛B 컨택트 스트립C 워크벤치D 수집 캘린더

P2 현상 대기최상단 레인스트립 라벨 배지라이트박스 CTA앰버 링 + 시트 CTA

추천: A를 상위 구조로, B를 컷 레이어로 (A+B 하이브리드)

보관함 최상위는 A(현상 대기 레인 → 월별 선반 → 컷 서랍)로 갑니다. 리텐션 훅을 수집 공간에 넣고(P2), 실제 커버 아트를 얻고(P7), v1.1의 테마 롤·여행 롤이 그대로 얹힙니다.

컷 서랍 안은 B(퍼포레이션 스트립 + 롤 색 점 + 3액션 선택 바)로 갑니다. 시각 차별화와 N:M 표현, 삭제 분리(P3·P4·P5)를 한 화면에서 모두 가져갑니다.

D는 A의 선반 위에 얹는 선택 뷰로 남깁니다(선반/달력 칩 전환). 구현 비용이 가장 낮아 먼저 붙여볼 수도 있지만, 테마 롤과 충돌하므로 주 구조로 두지 않습니다.

C의 두 조각만 흡수합니다 — 라이트박스 톤의 "현상 준비됨" 카드와 하단 축적 스탯. 상태 레인·스트릭 전면화는 대시보드화 위험 때문에 보류합니다.

어느 방향을 고르든 먼저 해야 하는 것

1. 데이터 소스 전환(P6). 컷 격자를 useLocalRecordings(파일 목록)에서 entities/clip 기반으로 옮깁니다. 무드·길이·방향·태그가 그때부터 UI에 쓸 수 있게 됩니다. 파일 어댑터는 원본 파일 I/O 전용으로 남깁니다.

2. 컷→롤 역인덱스 위젯. roll.clipRefs를 뒤집어 clipId → Roll[]을 만드는 read model이 A·B·D 모두에 필요합니다. 크로스 엔티티 조합이므로 widgets/에 둡니다(developed-rolls-shelf와 같은 이유).

3. 미현상 롤을 선반 read model에 포함. 현재 useDevelopedRolls는 developed만 통과시킵니다. 상태별로 나눠주는 read model이 필요합니다.

4. "빈 롤" 거짓 어포던스 제거. 지금의 장식용 점선 슬롯은 지우거나, 실제로 동작하는 것(월 빈칸 / 새 롤 프리셋)으로 바꿉니다.
